PaliGemma 2 mix · conflict between chart text and drawing · run 1 and follow-up runs 2–4

Bars or labels?

A chart can give one answer in its printed numbers and a different answer in its bars, slices and needles. Which one does PaliGemma 2 use?

Short answer. In most cases, the model uses the drawing. But this result is not as good as it looks, for the reasons below.
  • Value text. The model can read the numbers printed on the marks. If a question asks for a value, the model gives these numbers. On drawing questions, it usually does not use them. On these questions, 3B-448 uses them approximately two times as frequently as 3B-224.
  • Resolution. A follow-up run shows that most of the difference in text use between 3B-448 and 3B-224 does not come from image detail. With images reduced to the detail of 3B-224, 3B-448 used the text almost as frequently as before. Thus most of the difference comes from the checkpoint. These runs cannot separate the effect of the checkpoint weights from the effect of the larger 448 px input.
  • Scale text. On 3 charts, the text is scale text (axis numbers, a legend). The model never used this text, not even on the flipped version, where the text is correct. We asked directly which number is at the end of a flipped axis. The model rarely gave the correct number.
Does the model find the conflict? No.
  • Runs 3 and 4 asked the 3B and 10B models about the conflict. Some questions were direct ("do the numbers match the bars?"). Other questions were concrete ("is the number on the tallest bar the largest?").
  • On the conflict version, the model says that the numbers agree with the drawing approximately as frequently as on the normal version.
  • One part of the reason: on the conflict version, the printed numbers also change the answers of the model to drawing questions. Thus the model rarely has two different answers to compare.

1 · The gap

What the PaliGemma 2 paper measured, and what accuracy cannot show

Steiner et al. (2024, arXiv 2412.03555) give the accuracy on chart, document and diagram benchmarks. Each benchmark has its own fine-tuned model. The paper gives the results for each input resolution.

PaliGemma 2 3B, fine-tuned for each task: accuracy (%) at 224 px and 448 px
The numbers come from the tables in the paper. On tasks with much text, the accuracy increases the most with resolution. AI2D (the diagram task) changes only a little.

The paper itself says that text, document, screen and chart tasks improve mainly with resolution. For these tasks, a larger language model has less effect than resolution.

Why accuracy cannot show how the model read the chart

The model can answer a chart question in two ways: from the marks or from the printed numbers. On the normal version, the two ways give the same answer.

Normal version
"Which month sold more?"
From the bar heights: June
From the printed numbers: June
The two ways give the same answer. Thus a correct answer does not show which way the model used.
Same chart, false numbers
"Which month sold more?"
From the bar heights: June
From the printed numbers: January
If the two ways give different answers, the answer shows which way the model used.

What the paper does not test

  • No test in the paper separates the use of the marks from the use of the printed numbers.
  • The paper has no robustness tests: no text in conflict with the chart, no edited charts, no axes that mislead and no typographic attacks.
  • Most people download the mix checkpoints. These checkpoints are newer than the paper. The paper does not evaluate them. Every chart number in the paper comes from a fine-tune for one specific task.

Closest prior work: Deng et al. (CVPR 2025) put text that conflicts with the image into the prompt, next to the image. They find that the VLMs use the text. Mahbub et al. (IEEE VIS 2025) change the geometry of a chart, but its text stays correct. Their design is the opposite of our design. In this experiment, the text that conflicts with the drawing is in the pixels of the chart.

The gap. We know that PaliGemma 2 answers chart questions better at a higher resolution. We do not know if the higher accuracy comes from the drawing or from the printed numbers.
2 · Hypothesis

What we expected

H1. On charts that print their values, PaliGemma 2 gives answers from the printed text more frequently than from the marks. direction stated after the run

The plan asked the question without a direction: marks or text? We stated this direction after the run. It came from the resolution result of the paper. This direction was reasonable for these reasons:

  • In the paper, most of the increase in the chart scores comes from resolution.
  • Resolution helps mainly with small text.
  • If the increase comes from the printed numbers, it is possible that the model uses these numbers and not the marks.

3 · Design

One drawing, three versions

We draw each chart one time and render it three times. The pixels of the marks are identical in all three versions. Only the text changes. A pixel diff shows that all the changed pixels are on the text.

Normal version

The text agrees with the drawing. This version is the control. It shows if the model can give correct answers when there is no conflict.

Conflict version

Only the text changes. Thus, the text and the drawing give different answers. If the answer of the model changes, the text is the cause.

No-numbers version

We remove the text. This version is a baseline. It shows how well the model answers from the drawing alone.

Two types of conflict

11 charts · false numbers
Value text

On 9 charts, the value text is in value labels. On 2 charts, the value text is in large digital readouts. The conflict version swaps these numbers, puts them in reverse order or changes their sign. These conflict versions have no correct answer. An answer shows only a preference for the drawing or for the text.

3 charts · the text is correct
Scale text

The flipped version has a flipped or reversed axis (2 charts) or a reversed colour legend (1 chart). If the model uses only the drawing, it gives the wrong answer. If the model uses the scale text (the axis numbers or the legend), it gives the correct answer.

14 charts, 14 styles

The charts use five renderers: HTML/CSS, SVG, Canvas, matplotlib and PIL. Each chart has a different everyday style, from a newspaper page to a photographed journal article. We invented all the names in the charts. Thus, the answer cannot come from memory. Click a chart to see its six versions.

Checks in the design

  • Yes/no questions are in opposite pairs ("more?" and "fewer?"). If the model says yes to all questions, it says yes to both questions of a pair. Thus, a yes bias and correct answers give different results.
  • Each conflict version affects all questions. For each question, the text answer is different from the drawing answer.
  • Readable digits. The text is 19–48 px tall in the 896 px image. We checked it by eye at 448 px.
  • Checked scores. The rules could not match 98 different answers (212 of the 792 rows). Two independent LLM judges (separate Claude agents) examined these answers. The two judges agreed on all of them. We changed 4 outcomes, for example tltwy → TLWY. Each change applies to all images that have that answer.

                  11 · Run 3 · Direct questions

                  If we ask directly, the model does not find the conflict

                  Runs 1–2 measured whether the answer comes from the text or from the drawing. They never asked if the model finds the conflict between the numbers and the drawing. Run 3 asked this directly, on the 11 value-text charts (numbers on or next to the marks, and digital readouts). On these charts, the conflict version has false numbers.

                  Run 3 did not use the 3 scale-text charts. A flipped axis misleads, but the text and the drawing are consistent. Thus the question "do they match?" has no clear answer on these charts.

                  • Images. The normal version and the conflict version of each chart, in English and in Turkish: 44 images.
                  • Questions. Three yes/no questions for each image:
                    • do the numbers on the chart match the bars?
                    • do they contradict the bars?
                    • is there a mistake in this chart?
                    Each chart uses its own word for the marks in place of "bars" (slices, tree icons, gauges, rings…).
                  • Two opposite questions. We used them because run 1 showed a yes bias. If a model says yes to all questions, it says yes to "match" and to "contradict". Such a model finds no conflict.
                  • Models. Run 3 asked the two 3B models from the sections above (). Later, run 4 asked the same 132 prompts to PaliGemma 2 10B. This section also shows the 10B results.

                    What run 3 cannot separate. Two possible causes give the same flat dots:
                    • The model cannot compare the numbers with the drawing.
                    • The model does not understand a question such as do the numbers match?

                            The five questions

                              Run 2: the predictions and the results

                              The file timestamps show that we wrote the predictions approximately two and a half hours before run 2 started. We created run2/PREDICTIONS.md on 2026-10-07 at 07:16. The last edit before the run was at 10:53 on the same day. After the run, we added a note that corrects the date. The date 10-08 in the header of the file is a typo. There is no external record, for example a commit.

                              Open questions

                              • 28B, and real charts. The model did not find the conflict at 3B or at 10B. An 80 GB GPU is necessary for 28B. All charts here are synthetic. We made them so that only the text changes.
                              • Why the text changes the answers on some charts and not on others. The chart has a larger effect on the changes to the text answer than the text size. At 3B-448, answers on the TV thermometer readouts (s06) and on the battery widget (s13) change to the text answer at every text size. On the newspaper bars (s01) and on the spreadsheet (s14), no answer changes to the text answer at any text size. We did not test what these charts have in common. We also did not test if the questions on these charts are the cause.
                              • More scale charts, and a positive control. The scale result comes from 3 charts and 20 single answers per version. If we do not count the legend probe, it comes from 2 charts. A larger set of axes can test if the statement "sees the numbers but does not place them" is correct. This set can include:
                                • more flipped axes
                                • log axes
                                • normal axes with end numbers that are not the usual numbers.
                              • Which part of the model is the cause. 3B-448 and 3B-224 have different training and different input grids (1024 and 256 patches). Run 2 shows that image detail is not the main cause. These runs cannot show which of these two differences makes 3B-448 use the text more.

                              No run tested the fine-tuned ChartQA checkpoints that the paper reports. No run tested the 28B mix checkpoint. The 896 px checkpoint exists only as a pretrained checkpoint, not as a mix checkpoint.

                              15 · Read before you quote

                              Decisions and limits

                              Decisions that we made after we saw the data

                              • An answer to a Turkish question counts in either language. The model answered almost all Turkish yes/no questions in English. If we do not use this rule, almost all of these answers do not count.
                              • We changed 4 outcomes after two independent LLM judges agreed on them. For example, we read tltwy as TLWY. We read the answer -3° to "is it above freezing in Avlen?" as the text answer, "no". Each change applies to all images where that answer occurs. The report.txt of the notebook scores the answers with the rules only, before these changes. Thus, its 3B-224 numbers are a little lower.
                              • The direction of H1. We wrote down the direction of H1 (text more than marks) after the run. The planned question was two-sided.
                              • How we grouped the questions. The s02 question "in which year were the most thefts?" counts as a "which one" question. The s11 question "how many stocks went up?" counts as a direction question.
                              • How we scored runs 3–4. The rules could not clearly match some answers, which include Turkish sentences such as "Resimde hata var." (yes). Two independent LLM judges decoded these answers, but they did not score them. An answer counted only if both judges agreed (188 of 190 distinct answers). This did not change any result about whether the model finds the conflict.
                              • Run 2, decisions after we saw the answers:
                                • We removed the word question on the legend ("what word is at the top of the legend?"). The reason: on both versions, the answers gave the page title or a football club, not the legend.
                                • A scale version counts as "read" only if the model gives the correct answer to all number questions on it.
                                • Not in the predictions: the comparison of the answers of 3B-448 with less detail to the answers of each model. This comparison uses scored outcomes. An earlier version compared exact answer strings, and it made the agreement with 3B-448 too large.
                                • Not in the predictions: the accuracy and the answer habits of 3B-448 with less detail on normal versions.
                                • Not in the predictions: the interval on the part of the difference that less detail removes.
                                • Not in the predictions: the counts that use only the axis charts.
                              • The main result uses all answers. A stricter count uses only the questions with a correct answer on the normal version. It scores the yes/no questions per pair (3B-448: 62% drawing answer, 25% text answer). The main result uses all answers and shows the background rates next to it.

                              Limits

                              • A small sample. There are 14 charts. Thus, the 95% intervals are wide. The answers from one chart correlate with each other. For this reason, the intervals resample whole charts.
                              • Only 3 scale-text charts, and in practice only 2. On the legend chart (s10), the model is correct only 25–38% of the time, even on the normal version. The possible result that value text and scale text have different effects comes from these charts.
                              • The items are not independent: 2 languages × 14 charts. The intervals and the sign test at chart level correct for this. Counts at item level, for example 22 to 0, are descriptive.
                              • We did each run only one time. We used a greedy decoder and synthetic charts. Runs 1–3 used the 3B mix checkpoints. Run 4 used 3B and 10B. Only run 4 used 10B.
                              • Runs 3–4 are small. They use 11 charts and 22 images per dot. Here, "the model does not find the conflict" is this result: found ≈ false alarm in each model. The highest count of found is 4 of 22, with 3 false alarms. This result does not exclude a weak effect. Section 12 examines the decreases in drawing answers with 4 uncorrected tests per measure, and 2–3 of these tests are under p = 0.05.
                              • One form for each question. Run 4 added concrete forms and exact opposites. One of them is "is any smaller than the number above the shortest bar?". The model said "yes" to it on almost all normal versions. Thus, this question makes the count of "yes to both" too high.
                              • Runs 3–4 had no predictions with timestamps. The run-4 design states how to interpret the ladder. But we last edited its README after we received the answers.
                              • The no-numbers baseline removes the text. This is a larger change than a change of the digits. Thus, it gives only an approximate background rate.
                              • 3B-224 and 3B-448 are different checkpoints. Run 2 shows that image detail explains little of the difference in text use between the two checkpoints. 3B-448 still receives the images with less detail at 448 px. Thus, its digits stay two times as tall and cover four times as many patches as in the input of 3B-224. In this report, the word "checkpoint" includes the weights and the input grid.
                              • Run 2 is also small. The scale probe uses 3 charts and 12 versions per condition. The size sweep uses 4 charts with 4 drawing questions per size. The model gave a wrong answer to most read-through questions ("how many thefts in 2025?"), even on normal versions (4 of 16 correct). Thus, these questions could not show if the model used the drawing or the printed scale. The probe that tests if the model can read the scale has no positive control.
                              • One method to remove detail. Run 2 made the images smaller with a bicubic resampler. With the same resampler, the control gave exactly the same 3B-448 answers as run 1. Thus, this method agrees with the resize step of the model. But we did not try other methods to blur the images.
